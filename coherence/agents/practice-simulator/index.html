Operating design

This page describes the build I would actually sequence. It assumes an initial read-only pilot and preserves the named human decision before any external or irreversible action.

INPUTS

Persona, scenario, methodology and rubric

OUTPUT

Practice conversation and feedback

HUMAN DECISION

Learner and coach interpret feedback

Workflow summary

Trigger → retrieve governed context → normalize and validate → model reasoning with structured output → evidence and rule checks → human review → approved delivery or writeback → monitoring and feedback.

The workflow reads persona, scenario, methodology and rubric, produces practice conversation and feedback, and stops for review so learner and coach interpret feedback. Failures, low-confidence results, and missing evidence route to a manual queue.

How I would build it

Eight practical stages from charter to controlled production. The sequence is designed to expose data and governance problems before automation scales them.

01

Write the agent charter

Define the job as “Creates role-play scenarios and feedback using defined rubrics.” Name the business owner, intended users, success metrics, forbidden actions, medium-risk classification, and the decision that remains with a human: Learner and coach interpret feedback.

02

Map data and permissions

Inventory Persona, scenario, methodology and rubric. Confirm system owners, API scopes, retention, data classification, consent, and whether the agent may read, draft, or write. Start read-only and use synthetic data until approval.

03

Design the output contract

Create a versioned JSON schema for Practice conversation and feedback. Require source IDs, timestamps, confidence, missing-data flags, reasoning summary, and an explicit recommended human action.

04

Build ingestion and normalization

Use Web app connectors and n8n to pull only the required fields. Normalize IDs and dates, deduplicate records, reject incomplete payloads, and log provenance before the model sees anything.

05

Implement the reasoning workflow

Retrieve approved context, assemble bounded instructions and examples, call the selected model with structured output, validate the response against schema and business rules, and route failures to a safe queue.

06

Add the human control

Present the draft and its evidence in the user’s existing workflow. Require learner and coach interpret feedback. Do not enable automatic external communication, record changes, or customer-impacting action in the first release.

07

Evaluate before release

Create 50–200 representative test cases, including missing data, contradictory evidence, edge segments, and adversarial inputs. Score accuracy, groundedness, usefulness, bias, false positives, latency, and cost against the current manual baseline.

08

Pilot, monitor, and scale

Pilot with 5–10 users for four weeks. Log prompts, sources, outputs, approvals, overrides, errors, latency, and spend. Review weekly, add rollback and kill-switch procedures, and expand only after the named owner accepts residual risk.

Expected impact and economics

Impact should be measured against the current manual baseline. A compelling demo is not evidence of durable value.

Impact hypothesis

Expands deliberate practice access and provides consistent rubric-based feedback; does not replace manager coaching.

Monthly cost basis

$150–$1,000 for model calls, orchestration, incremental storage, and agent-specific data usage at the stated volume. Existing enterprise systems and implementation labor are excluded.

Cost range is a planning estimate, not a vendor quote. Current reference points include usage-based model APIs, n8n execution pricing, and Clay plans/actions/data credits. Enterprise security, observability, premium data, and vendor minimums can materially increase total cost.
